# Подключение «1С:Управление торговлей»

Репрайсер поддерживает прямое чтение опубликованной типовой УТ 11 через стандартный OData и готовый JSON-снимок через HTTP. [Официальная онлайн-демонстрация УТ](https://v8.1c.ru/trade/onlayn-demonstratsiya-1s-upravlenie-torgovley-8/)

## Подключение готового JSON-снимка

1. Разверните доступную вам демо-конфигурацию «Управление торговлей» на платформе «1С:Предприятие». Зафиксируйте версию конфигурации, склад и вид учётной цены.
2. Создайте позиции из сценария показа. Подготовьте остатки, продажи, себестоимость, учётные цены и ожидаемые поступления через заказы поставщикам. Для TX-201 оставьте срок пустым и подготовьте 15 дней наличия. Значения для наполнения можно посмотреть в `demo.py`.
3. Опубликуйте HTTP-сервис в расширении 1С или промежуточную выгрузку из опубликованной базы. На стороне 1С сформируйте агрегаты по артикулу и выбранному складу. Продажи и наличие отдавайте по календарным дням, включая дни без продаж. Для поставки отдавайте остаток к получению по открытым заказам. Поля и регистры сопоставьте с метаданными установленной редакции.
4. В «Интеграциях» укажите адрес публикации, например `https://demo.example.ru/trade`, и путь `hs/repricer/snapshot`. Укажите логин и пароль пользователя 1С с доступом к HTTP-сервису, сохраните настройки и проверьте соединение. Репрайсер запрашивает конечный адрес через HTTP Basic. Используйте HTTPS в сети, чтобы защитить учётные данные в запросе.
5. Запустите синхронизацию вручную или задайте ежедневное время по Москве. Панель показывает последнюю плановую попытку, успех синхронизации и ошибку источника.
6. Пройдите приёмку по KM-101. Измените дату в заказе поставщику, синхронизируйте и сверяйте дату, количество и изменение рекомендации. Для новой базы запускайте панель с новым файлом состояния, так как начальная цена WB инициализируется учётной ценой только при первом появлении артикула.

Публикация веб-клиента сама по себе не предоставляет снимок товаров. Для этого нужен опубликованный HTTP-сервис, возвращающий JSON по контракту ниже. [HTTP-сервисы платформы 1С](https://v8.1c.ru/platforma/http-servisy/)

Для ранее сохранённого полного URL оставьте путь пустым. Сервер сохраняет пароль в локальном файле состояния с ограниченными правами доступа. Пустое поле пароля сохраняет его для того же адреса, пути и логина. Чтобы отключить вход с паролем, очистите логин и сохраните настройки.

## Формат HTTP-ответа

Метод GET возвращает массив товаров в JSON с кодировкой UTF-8. Пример сокращённого снимка:

```json
[
  {
    "sku": "KM-101",
    "name": "Кофейная кружка",
    "category": "Посуда",
    "stock": 30,
    "cost": 550,
    "accounting": 1000,
    "sales": [
      {"date": "2026-11-23", "available": true, "units": 10}
    ],
    "supplies": [
      {"date": "2026-12-04", "quantity": 80}
    ]
  }
]
```

`cost` допускает null, неизвестная поставка передаётся пустым массивом или с null в поле даты. Каждый день продаж должен встречаться один раз на товар. Для отчёта сравнения 30-дневных периодов желательно передать 60 дней истории. Реализация клиента находится в `adapters.py`, пример ответа можно получить с `demo.py`.

## Прямое подключение типовой УТ 11 через OData

В «Интеграциях» выберите «Типовая УТ 11 · OData». Укажите адрес веб-публикации, логин пользователя 1С, склад, организацию и вид цены. Для склада, организации и вида цены принимаются точные названия или GUID. Если у пользователя 1С пустой пароль, поле можно оставить пустым. Сохраните настройки, проверьте соединение и нажмите «Синхронизировать сейчас».

Адаптер сам добавляет `/odata/standard.odata` к адресу публикации и принимает URL веб-клиента с окончанием `/ru/`. Пользователю 1С нужны права чтения опубликованных справочников, регистров и строк заказов. Адаптер выполняет GET-запросы и не записывает данные в УТ.

- Каталог строится по позициям с остатками, продажами или ожидаемыми поставками выбранного склада. Включаются позиции с действующей рублёвой ценой за базовую единицу выбранного вида цены. Ключ товара состоит из ссылки номенклатуры и, при наличии, ссылки характеристики. В таблице отображается артикул из 1С.
- Остаток — физическое наличие по регистру «Товары на складах». История на 60 дней строится по остатку на начало периода и проведённым движениям. День считается днём наличия при положительном остатке на начало или конец дня либо при продаже. Продажи ограничены складом и организацией, учитываются розничные и клиентские реализации, комиссионные продажи и возвраты. Учёт отдельного канала WB зависит от разметки базы.
- Себестоимость единицы — стоимость и дополнительные расходы управленческого учёта, поделённые на остаток выбранной организации в разделе «Товары на складах». Когда расчётной суммы нет, значение остаётся пустым. Для цены читаются оба опубликованных регистра, включая `ЦеныНоменклатуры25`.
- Поставки берутся из положительного остатка к поступлению по строке проведённого заказа. Строки с отменой, без даты или с прошедшей датой не включаются. Частично полученная строка учитывается по остаточному количеству.

Тестовая УТ вернула товарные данные для сочетания «Центральный склад», «Торговый дом „Комплексный“», «Розничная». В этой базе проверенные движения относятся к историческому периоду, поэтому текущий отчёт может показывать нулевые продажи и отсутствие будущих поставок.
