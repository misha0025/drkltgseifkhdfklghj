# Передача контекста

В обсуждении ТЗ закрепили четыре решения. Поставка приходит из 1С, шаг фиксирован внутри категории, ограничения проверяются до отправки, MCP исключён из объёма. Для прототипа выбраны маржа от выручки, складской агрегат по номенклатуре и характеристике и московское время расчётов.

## Ориентиры в коде

- `engine.py` вычисляет предложение из снимка товара, состояния площадки и правил.
- `ut_odata.py` собирает снимок из стандартного OData УТ.
- `adapters.py` загружает снимок и реализует очередь имитатора WB.
- `app.py` ведёт синхронизацию, историю и состояние. Ревизия цены защищает от подтверждения после ручного изменения в WB.
- `static/` содержит интерфейс. `demo.py` отдаёт повторяемые данные по HTTP. `tests/` содержит приёмочные проверки.

## Упрощения и следующие доработки

- Прямое чтение типовой УТ уже реализовано. Для новой базы проверьте состав OData и сверяйте остаток, себестоимость и поставку по одной позиции с отчётами УТ.
- Отчёт использует продажи и наличие по дням, а остаток, цены учёта и затраты берёт из текущего снимка. Для ретроспективной маржи нужны исторические цены, расходы и остатки.
- Сервер локальный и однопроцессный. Для совместной работы потребуются БД, идемпотентная очередь, доступ пользователей и мониторинг.
- Синхронизация запускается вручную или по ежедневному расписанию в Москве. Для эксплуатации можно добавить журнал попыток, повторные попытки и контроль свежести данных.
- При переходе от имитатора к площадке потребуется отдельный адаптер с обработкой статусов и сверкой цен. Расчёт цен остаётся в `engine.py`.
